Ce qu'un audit de code ne remplace pas

non faitBuild Xcode réel de l'app macOS (le typecheck laisse passer des erreurs de projet).
non faitValidation de bout en bout avec Ollama sur un vrai document après les correctifs (tests/validate_translation.py).
non faitAucun test automatisé de l'interface web ; essai sous Windows jamais fait.

Limite de la méthode : la skill ne retient que les constats notés 80 ou plus. Un audit sans constat prouve qu'aucun défaut à 80 ou plus n'est apparu, pas qu'il n'y en a aucun. Les scénarios n'ont pas été exécutés, sauf pytest.

Règles pour les nouveaux développements :

  1. Tout nouveau code passe par /revue-code avant push et reçoit un test.
  2. Toute valeur venue de l'API est validée à la création, pas au moment où elle sert.
  3. Toute suppression se propage aux deux sources (JSON et store).
  4. Les pièges du produit sont dans .claude/revue-pieges.md : un défaut trouvé s'y ajoute.
